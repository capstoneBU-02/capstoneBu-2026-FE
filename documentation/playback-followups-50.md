# #50 재생·오류 안내 FE 후속 결정

2026-11-16, develop `0695feb`와 기존 재현 기록을 기준으로 FE 독립 보완과 실환경 확인을 구분했다. 정상 사용자 클릭에서 재생이 항상 멈춘다는 결함 판정은 하지 않는다.

## 재생 시작 대기

출력 재개 Promise가 미완료인 동안 ‘재생 시작을 기다리고 있어요’와 ‘재생 시작 취소’를 표시한다. 취소는 예약한 소스를 정지·분리하고 현재 위치를 보존한다. 사용자는 같은 버튼으로 다시 재생할 수 있다. 구간 이동·트랙 교체·이탈로 폐기된 소스의 늦은 성공과 거절은 현재 상태를 바꾸지 않는다. 같은 소스를 유지한 구간 변경의 응답은 여전히 유효하다.

3초 등 고정 시간을 오류 판정 기준으로 추가하지 않는다. [Web Audio resume 명세 초안](https://www.w3.org/TR/webaudio/#dom-audiocontext-resume)은 시작이 허용되지 않을 때 Promise를 대기 목록에 보관한다. 이번 상태는 앱이 요청한 재개를 기다리는 경우이며, 이미 재생 중인 출력을 OS가 중단하거나 장치를 바꾸는 모든 경우를 처리했다는 의미가 아니다.

## 반복 오류와 진단

같은 음원의 동기 실패도 회차마다 alert 인스턴스를 바꾼다. 알림 때문에 키보드 초점을 이동시키지 않으며 실패 안내는 성공적인 새 시도나 해당 음원 이탈 전까지 유지한다. [WAI alert 패턴](https://www.w3.org/WAI/ARIA/apg/patterns/alert/)을 따른 구조 보완이며 DOM 교체만으로 VoiceOver/NVDA의 실제 재낭독을 보증하지 않는다.

진단에는 `context`·`source`·`start`·`resume` 단계와 허용 목록의 오류 이름만 전달한다. 목록 밖 이름이나 읽을 수 없는 예외는 `unknown`이다. 로컬 콘솔의 `[earmark:audio-output]` 기록에는 원문 메시지·스택·파일명·URL·음원·작업 ID를 넣지 않는다. 진단 출력이 실패해도 사용자 복구를 방해하지 않는다. 원격 수집이나 저장 인프라는 이번 범위가 아니다.

## 안내 UI와 기여 문서

재생·내려받기 오류 및 재생 대기 안내는 같은 표면·여백·글꼴·줄바꿈 스타일을 사용한다. 동작 버튼의 역할은 유지한다. 한국어는 단어 단위로 줄바꿈하고 긴 토큰은 컨테이너 안에서 나눌 수 있다. 플레이어 위의 고정 안내 위치는 유지하며, 위치 변경은 별도 UX 결정으로 남긴다.

CONTRIBUTING과 PR 템플릿은 현재 GitHub 기본 브랜치가 develop임을 명시한다. 자동 종료의 기술적 동작과 `Refs`·완료 확인 후 수동 종료 운영 정책을 구분하며, 배포 기준 main과 혼동하지 않는다.

## 검증과 남은 범위

일반 재생 클릭이 동작하는 것을 확인한 뒤 대기·실패를 주입하여 취소, 재시도, 늦은 응답, 반복 알림, 진단의 민감정보 제외를 검증한다. 320·390px에서 동시 오류 안내와 재시도·재생 버튼의 접근 가능 여부를 확인한다. 최종 커밋의 전체 검사·CI·리뷰 결과는 연결 PR에 기록한다.

실제 화면 낭독기의 반복 실패 발화, Safari·모바일 실기기의 백그라운드 복귀·장치 전환, 원격 진단 수집 및 고정 안내 배치 정책은 #50에 남긴다. Chromium의 응답 주입 테스트를 해당 실환경 검증으로 해석하지 않는다.
