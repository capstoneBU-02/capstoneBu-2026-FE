# Earmark 요구사항 검토 기록

검토일: 2026-11-01 · 목적: API 확정 전 목업 화면 개발의 기준·범위·미확정사항 정리

로컬에서 발견한 기획·정책·UI·기술·리서치·제안서와 공유 기능명세를 확인했다. 첫 구현은 워크스페이스에 이미 진입한 상태의 내 작업 목록, 빈 상태, 선택 동의 변경으로 제한한다. **AI 기술설계 원본은 접근할 수 없었고 실제 API 명세는 확인되지 않았다.** 해당 한계를 유지한 채 목업을 구현한다.

## 자료 우선순위와 확인 범위

1. 사용자의 최신 지시와 [공유 Google Sheets 기능명세](https://docs.google.com/spreadsheets/d/1Lv2dwjHSNSimr06ntmF7oXVtmqvNeo5aJTSLNAqNX_0/edit?usp=sharing)의 해당 도메인·정책 행을 기능 기준으로 삼는다. 공유시트 담당은 팀 협업의 기준이다.
2. 시각은 사용자가 지정한 [Earmark Figma 파일](https://www.figma.com/design/87W9ZPWGTWqNHX7HTfQ1kZ)의 최신 프레임을 따른다. Figma 담당 에이전트가 실제 디자인을 별도로 확인했다. 문서 담당은 로컬 노드 목록과 정책의 일치 여부를 확인했다.
3. 로컬 기능명세 v0.3, 정책 결정사항 9/17 갱신본, 기획 v0.4를 상세 근거로 사용한다. live와 불일치하면 변경 이유·범위를 확인해 문서와 목업을 함께 갱신한다.
4. UI v3·노하우는 현재 화면 설명이다. 제안서·기술스택·AI 기술 검토는 설계 참고이며, 과거판·리서치·비용 시나리오는 현재 결정과 분리한다.

공유시트는 브라우저에서 읽기 전용으로 열어 `차수별 정책`, `카피작업`, `정책결정` 탭의 셀 내용을 확인했다. 다른 도메인의 세부 정책은 로컬 v0.3 전 시트에서 확인했다. 따라서 live 전체 워크북이 로컬과 셀 단위로 완전히 같다고 단정하지 않는다. 문서 원문이나 외부 문서를 수정하지 않았다.

## 공유 기능명세와 담당

검토한 live 탭:

- [차수별 정책](https://docs.google.com/spreadsheets/d/1Lv2dwjHSNSimr06ntmF7oXVtmqvNeo5aJTSLNAqNX_0/edit?gid=1471858855#gid=1471858855): 개발 담당과 차수별 기능 확인.
- [카피작업](https://docs.google.com/spreadsheets/d/1Lv2dwjHSNSimr06ntmF7oXVtmqvNeo5aJTSLNAqNX_0/edit?gid=19488396#gid=19488396): COPY-01~04 모두 PoC1 유지, 로컬 v0.3과 정책 일치.
- [정책결정](https://docs.google.com/spreadsheets/d/1Lv2dwjHSNSimr06ntmF7oXVtmqvNeo5aJTSLNAqNX_0/edit?gid=40091315#gid=40091315): D01~D24 확인, 로컬 결정 내용과 일치. 결정 담당 칸은 공란.

| 실제 팀원 | live `개발 담당` 기능                 | 추가 근거·주의                             |
| --------- | ------------------------------------- | ------------------------------------------ |
| 서지영    | ACC-02·06·07, IN-01~05, DATA-01·02·05 | 워크스페이스·입력·자료                     |
| 구민성    | SEG-01~04, REC-01~04                  | 수동 구간·연주 입력                        |
| 국태양    | JOB-01~05, CMP-01~05                  | 처리·비교                                  |
| 복재환    | TAB-01~04                             | TAB-04는 `복재환(추후 확장성)`             |
| 김효찬    | live 요약에 COPY 담당 행 없음         | 제안서의 PM/FE·COPY-01~04 담당 근거와 구분 |

3차 이후 기능의 개발 담당과 정책결정 담당은 live 확인 범위에서 공란이다. 미기입을 임의로 배정하지 않았다. 임시 에이전트 분업은 [구현 계획](implementation-plan.md)의 별도 표에 있다.

`차수별 정책` 집계는 PoC1 24개, PoC2 9개, 운영 기본 26개, 서비스 확장 12개, 상용화 4개로 **75개**다. 개별 도메인에는 COPY-01~04가 별도로 존재하여 로컬 v0.3 기능 전체는 **79개**, PoC1은 **28개**, PoC1+2는 **37개**다. 집계에서 빠졌다는 이유로 COPY를 삭제하거나 PoC1 밖으로 옮기면 안 된다.

과거판 변화는 v0.1→v0.2에서 9/15 정책 구체화와 EXT-09~12 추가, v0.2→v0.3에서 ACC-06/07 및 D23/24 추가·워크스페이스 소유로 변경·차수별 정책 탭 추가다. 특히 과거 로그인/JWT 계획을 PoC1에 적용하지 않는다.

## 렌더링·검증 방향

첫 목록에는 오디오·악보 엔진을 넣지 않는다. 실제 작업 공간 단계에서 파형과 악보를 route/기능 경계로 지연 로딩하고, 재생 clock이 목록·셸 전체를 반복 렌더링하지 않게 한다. 악보 wrapper는 생성·갱신·해제를 분리하고 고정 악보 fixture로 먼저 검증한다. 파일 blob을 일반 목록 캐시에 오래 보관하거나 렌더마다 엔진을 재생성하지 않는다.

검증은 타입/정적 검사·빌드, 저장소/훅의 의미 있는 비동기 동작, 실제 브라우저의 상태·키보드·반응형으로 나눈다. 실제 API·음원·악보가 없는 첫 목업 결과를 전체 PoC 완료나 성능 검증 완료로 보고하지 않는다. 단계별 범위와 acceptance는 [구현 계획](implementation-plan.md)을 따른다.
