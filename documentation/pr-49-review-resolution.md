# PR #49 리뷰 반영 결정

PR #49는 오디오 재개 거절의 복구, 실패 단계 문구, 음원 재시도 후 키보드 초점 표시를 다룬다. 2026-11-16 후속 검토에서는 위치 보존 테스트와 상세 실패 단계 정합성을 보강했다. BE 계약과 실제 API 연동은 별도 범위다.

## 이번 PR에 반영

- 탐색 후 재개가 거절되거나 소스 시작이 동기적으로 실패할 때 새 위치를 보존하고 그 위치에서 재시도하는 단위 테스트 두 개를 추가했다. 임시 복사본에서 각각의 위치 저장 코드를 제거하면 해당 테스트가 실패하는 것을 확인했다.
- 상세 머리글은 본문과 같은 `detail.stages`에서 실패 단계를 읽는다. 공통 문구 함수 `taskHeadlineStatus`는 실패 단계를 필수 인자로 받아 음원 유무로 다시 계산하지 않는다.
- 단계가 없는 목록은 입력 음원 종류와 작업 상태로 단계를 계산한다. 곡을 찾을 수 없을 때의 기존 fallback은 유지한다. 명시적인 상세 단계가 계산값과 다른 두 조합을 브라우저에서 검증했다.
- 목록과 상세가 서로 다른 데이터에서 항상 같은 문구를 만든다고 보장하지 않는다. 상세 안에서 머리글·본문이 같은 단계 정보를 사용하도록 한 변경이며, 현재 목업에서 목록은 기존 단계 계산을 유지한다.

## 검증 범위와 표현

- 상세 단계 불일치의 단위·브라우저 테스트가 수정 전 실패하고 수정 후 통과했다. 기존 목록의 분리 실패 및 두 파형 재시도 경로도 함께 검증했다.
- 위치 저장 코드를 제거하는 실험은 임시 복사본에서만 실행했다. 높은 실행 라인 커버리지를 회귀 검출력이나 FE 전체 완성도로 해석하지 않는다.
- 늦은 resume 거절을 무시하는 조건은 소스가 해제되거나 교체된 경우다. 구간 변경 시 같은 소스가 유지되면 그 요청의 거절은 현재 재생 실패로 처리한다.
- Playwright의 `page.evaluate()`는 사용자 동작을 주입한다. 사용자 활성화가 없는 재개를 조사할 때는 이를 통제하고 실제 활성화 상태를 함께 기록한다.
- 실패 주입으로 확인한 Chromium 동작과 실제 장치 장애·Safari·화면 낭독기 검증을 구분한다. 대기 3초 관찰만으로 영구 정지나 적절한 실패 제한 시간을 확정하지 않는다.

프로젝트 검사와 전체 브라우저 회귀 결과 및 최종 검토 커밋은 PR #49의 검증·리뷰 기록에서 확인한다.
