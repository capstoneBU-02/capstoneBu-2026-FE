# #29·#35 FE 후속 반영 결정

2026-11-16, develop `992281a` 기준으로 이슈 체크리스트를 현재 구현·테스트와 대조했다. 이름 번호 제안·정책 밖 값 안내·여러 번 수정한 결과의 순서 테스트, 하네스 분리와 재조회 루프 분리·단위 테스트는 이미 반영돼 있었다. 미체크 개수를 미구현 개수로 사용하지 않는다.

## 요청과 상태 복구

- 재시도 응답이 실패해도 재조회한 작업이 더 이상 같은 실패 패널을 사용하지 않으면 본문으로 초점을 옮긴다. 요청을 시작한 뒤 사용자가 다른 조작부로 초점을 옮겼거나 화면을 떠났으면 이동시키지 않는다. 네트워크 재조회 실패는 보이던 결과를 유지한다.
- 동의 저장 중 네이티브 닫힘은 해당 창 인스턴스를 보존한다. 실패하면 제목에 초점을 두고 오류가 있는 창을 다시 열며 성공이면 닫는다. 오류는 제목 아래에 두어 320×480에서도 바로 보이게 한다. 사용자가 명시적으로 다시 열면 새 인스턴스를 사용하므로 이전 저장 완료가 새 창을 닫지 않는다. 화면·세션 이동으로 해제된 창은 다시 열지 않는다.
- 멈추기 요청 중 닫힌 창은 머리글 버튼으로 다시 열 수 있다. 진행 중 요청은 그대로이며 확인 버튼은 중복 요청을 만들지 않는다.
- 수동·백그라운드 재조회는 같은 상태 변환을 사용한다. 네트워크 오류는 기존 결과와 실패 표시를 유지하고, 접근 불가·만료는 결과를 제거한다. 다른 요청의 응답은 상태를 덮지 않는다.
- 곡 추가·파일 바꾸기·다른 파일 올리기는 구별 가능한 요청 타입으로 표현한다. 파일 바꾸기에만 원래 곡과 입력 종류가 있고, 다른 파일 입력에만 새 구간 초안이 있다.

## 화면 표시

- 상세 처리 본문은 실행 중인 단계에 따라 기타 분리/타브 생성 제목을 표시한다. 진행률 null은 움직이는 막대와 ‘진행률 확인 중’으로 0%·대기와 구분하며 숫자를 추정하지 않는다. 동작 줄이기 설정에서는 막대의 이동을 멈춘다.
- 편집할 작업을 아직 불러오지 못했으면 머리글은 ‘작업 불러오기’다. 작업을 받은 뒤 구간 수정/다시 정하기를 구분한다.
- 이전 결과는 기존 모델의 비교 수·카피 상태와 순번을 표시한다. 최신순 배열에서 오래된 항목부터 번호를 매기므로 새 결과가 앞에 추가돼도 기존 순번은 유지된다. 서버의 영구 식별자나 생성 시각을 뜻하지 않는다.
- 이전 결과의 모델은 메타 정보다. 안내에서도 이전 음원·타브·비교 상세를 다시 열 수 있다고 약속하지 않는다. 구간·파트·튜닝을 바꿀 때 새 타브를 만드는 사실과 보관하는 정보만 설명한다.

## 검증과 남은 범위

새 브라우저 회귀의 최초 실행에서 실제 동작 차이 8건이 실패했고, 같은 경로가 수정 후 통과했다. 저장 실패/성공·명시적 재진입·화면 이동, 응답 실패 뒤 상태 변경과 초점 유지, 멈추기 창 재진입·중복 제출, 진행률 미제공·동작 줄이기, 로딩 제목, 동일 범위로 돌아온 이전 결과·세 가지 카피 상태를 검증한다. 전체 검사·CI·최종 커밋의 결과는 연결 PR에 기록한다.

#29에는 구간 수정 거절의 서버 오류 계약, 중복 이름 정책, 이전 결과의 생성 시각·지속적 식별·재열람 범위가 남는다. #35에는 분리 음원의 결과 식별·버전·URL 만료 계약이 남는다. 두 이슈는 이번 FE 반영만으로 닫지 않는다.

실제 API 연동, Safari·모바일 실기기·화면 낭독기 검증은 Chromium 목업 회귀와 구분한다. 재생 대기 UX·반복 오류 낭독·진단·공통 오류 안내 UI·기여 문서의 브랜치 설명은 #50에서 별도로 추적한다.
