# 테스터 코드 진입·최초 이용 안내 목업 구현 계획

작성: 2026-11-04 · 관련 이슈: [#7](https://github.com/capstoneBU-02/capstoneBu-2026-FE/issues/7) · 작업 브랜치: `feature/7-access-onboarding-mock`

기존 구현 계획의 2A와 2B를 연결해 **테스터 코드 입력 → 최초 이용 안내 → 선택 동의 → 내 작업** 흐름을 구현한다. 신규 진입에서 이용 안내가 빠지지 않도록 하나의 PR로 검증하며, 재방문은 해당 목업 워크스페이스의 기존 안내 확인·동의 상태를 따른다. 아래 항목은 구현·검증 기준이며, 문서 작성 시점에 완료되었다는 뜻이 아니다.

## 구현 범위

1. 기본 진입에서 랜딩과 테스터 코드 입력을 제공한다. 이름·이메일 등 계정 정보는 수집하지 않으며 코드를 공유하지 않도록 안내한다.
2. 코드 확인 중에는 중복 제출을 막는다. 빈 입력, 무효·만료·폐기된 코드, 일시 제한, 요청 실패를 표시하고 가능한 수정·재시도 경로를 제공한다.
3. 유효한 신규 목업 워크스페이스는 이용 안내 1/2 → AI 학습 활용 2/2 순서로 진행한다. 이용 안내는 안내 확인으로 다루고, 확정되지 않은 약관 서명이나 개인정보 수집 항목을 만들지 않는다.
4. 학습 활용은 기본 미선택이다. 동의·거부를 같은 무게로 제공하고 나중에 선택할 수 있다. 거부·미선택 상태에서도 기존 목록과 필터를 이용한다.
5. 동의·거부의 저장 성공 또는 명시적인 나중에 선택 이후에만 `onboardingCompleted`를 참으로 바꾸고 목록으로 이동한다. 화면 표시·이용 안내의 다음 버튼·실패한 저장을 온보딩 완료로 취급하지 않는다.
6. 재방문은 같은 워크스페이스의 온보딩 완료 여부와 동의 상태를 따른다. 완료한 재방문은 목록으로 이동하고, 작업이 있는 미선택 목록에는 기존 배너를 표시한다. 빈 상태는 기존 Figma의 파일 선택 안내를 유지하며 설정에서 선택을 바꿀 수 있다. 완료하지 않은 상태는 남은 안내·선택 흐름을 제공한다.
7. 온보딩과 목록이 같은 인메모리 워크스페이스 상태를 공유한다. 온보딩에서 저장한 선택을 목록 진입 시 초기화하지 않으며, 목록에서 변경한 선택도 같은 저장소에 반영한다.
8. 기존 목록의 세션 만료 안내에서 코드 재입력으로 복구할 수 있게 한다. 만료·진입 전환 뒤에 이전 요청의 결과가 다시 나타나지 않도록 요청 수명을 정리한다.

설정·도움말 전체 화면(2C), 파일 업로드, 처리 시작, 작업 상세, 오디오·악보·녹음·비교, 실제 서버 인증과 CD는 이번 범위에 포함하지 않는다. 해당 미구현 기능을 완료된 동작처럼 표시하지 않는다.

## 내부 모델과 목업 가정

저장소 인터페이스는 FE 화면용 계약이며 서버 endpoint·DTO·오류코드를 확정하지 않는다. 진입·온보딩 상태와 워크스페이스 식별자를 구분하고, 선택 동의는 기존 `undecided`·`accepted`·`declined` 모델을 유지한다.

| 항목            | 이번 구현 기준                                                                                                | 실제 연결 시 필요한 결정                              |
| --------------- | ------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------- |
| 코드            | 설정·fixture의 예시 코드로 시나리오를 재현한다. 제출 코드를 URL·브라우저 저장소·로그에 기록하지 않는다.       | 형식·발급·유효기간·재발급·폐기 방식                   |
| 입력 실패 제한  | 별도 목업 응답으로 일시 제한 상태를 표시한다. 임의 실패 횟수나 초 단위 카운트다운을 정책으로 추가하지 않는다. | 횟수·제한 시간·해제 조건                              |
| 워크스페이스    | 같은 코드가 같은 인메모리 워크스페이스를 가리키게 한다. 온보딩과 목록에서 같은 저장소 상태를 사용한다.        | 실제 소유권 검증·동시 기기·자료의 계정 이전           |
| 세션            | 앱 메모리로 진입 상태를 시연한다. 실제 인증 토큰이나 JS 쿠키를 만들지 않는다.                                 | 서버의 HttpOnly 워크스페이스 세션·만료·폐기 응답      |
| 새로고침·재방문 | 현재 앱 수명 동안의 재진입과 재방문 fixture를 검증한다. 새로고침하면 메모리 상태를 초기화한다.                | 브라우저·기기를 바꿔도 같은 코드로 복구되는 서버 저장 |

| 학습 활용 선택  | 저장 성공 시에만 선택을 갱신한다. 나중에 선택은 미선택을 유지하고 온보딩만 완료한다.                          | 자료 범위·목적·기간·철회·동의 버전·실패 응답          |

프론트 목업의 경로 분기는 실제 접근 제어나 서버 동의 기록을 대신하지 않는다. 실제 API adapter를 붙일 때 ACC-02의 소유권과 ACC-07의 세션·폐기 처리를 별도로 검증한다.

목업 진입은 신규·재방문·다른 워크스페이스에 대응하는 명시적 데모 코드 허용 목록만 성공시킨다. 목록에 없는 임의 문자열은 무효로 처리한다. 이 목록은 테스트 fixture이며 서버의 코드 형식·검증 규칙을 확정하지 않는다. 구체적인 예시 코드와 시나리오 URL은 [README](../README.md)에서 관리한다.

아래 시나리오의 URL·fixture 이름은 구현 후 README에 기록한다. 설정용 시나리오와 사용자가 제출한 코드를 구분하며 제출 코드를 URL에 넣지 않는다.

- [x] 신규 정상 코드로 진입하면 이용 안내 1/2 → AI 학습 활용 2/2 → 내 작업 순서로 이동한다.
- [x] 이용 안내를 표시하거나 다음으로 진행한 것만으로 온보딩 완료·학습 동의가 저장되지 않는다.

- [x] 재방문 accepted·declined·undecided 상태가 보존되고, 완료하지 않은 온보딩을 건너뛰지 않는다.
- [x] 동의 거부·미선택에서도 목록과 필터를 이용한다.

- [x] 같은 코드 재입력은 같은 목업 워크스페이스를 열고, 다른 워크스페이스의 선택·자료가 섞이지 않는다.

- [x] 1440px와 390px 화면에서 긴 문구와 오류가 겹치거나 주요 조작을 가리지 않는다.
- [x] 기존 저장소·브라우저 회귀 테스트를 유지하고 새 진입·온보딩·복구의 실제 App 흐름을 검증한다.
